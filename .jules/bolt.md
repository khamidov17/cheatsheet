## 2026-07-03 - Debounced Parallel Persistence & Conditional Rendering
**Learning:** In applications where state persistence triggers expensive UI re-renders (like a full history grid update), debouncing the save operation is only half the battle. If the save operation itself triggers a re-render even when the updated component is not visible (e.g., updating the history grid while in the editor view), it wastes CPU cycles and memory. Additionally, sequential network requests for multi-destination persistence (local vs user) can be parallelized to reduce total "time-to-safe" state.
**Action:** Always wrap global UI update functions (like `renderHistory()`) in visibility checks or view-state checks to ensure DOM manipulation only occurs when the target element is actually on screen. Use `Promise.all` for independent network operations to minimize latency.
