## 2025-05-14 - Redundant sequential persistence and DOM re-rendering
**Learning:** In the current architecture, document persistence (`saveHistory`) and UI rendering (`renderHistory`) were tightly coupled to every single 'input' event in the editor. This caused a performance bottleneck where each keystroke triggered two sequential network requests and a full DOM rebuild of the history list, leading to UI stutter and excessive API traffic. Parallelizing the API requests via `Promise.all` and debouncing the entire persistence flow (while conditionally skipping UI renders when the landing view is inactive) significantly improves responsiveness.
**Action:** Always implement debounced parallel persistence for real-time editors. Ensure immediate persistence ('flush') on critical navigation or structural changes (like reordering/deletion) and before page unload to prevent data loss.
