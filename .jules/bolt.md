## 2025-05-14 - Debounced History Persistence
**Learning:** In a single-page application with heavy DOM manipulation and frequent state updates (like a contentEditable editor), debouncing persistence is critical to avoid network saturation and server-side race conditions. Using `keepalive: true` in `fetch` and flushing the debounce queue on `beforeunload` ensures data integrity even during aggressive user exits. Additionally, critical state changes (like node reordering or deletion) must bypass the debounce to provide immediate consistency.
**Action:** Always implement a `debounce` with `.flush()` and `.cancel()` capabilities for auto-save features, and ensure `this` context is preserved in the debounced wrapper. Use `async/await` properly when persistence is required before UI transitions.
